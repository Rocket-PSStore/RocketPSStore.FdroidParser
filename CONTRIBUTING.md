# Contributing to RocketPSStore.FdroidParser

Thank you for your interest in contributing to RocketPSStore.FdroidParser! We welcome contributions from developers of all skill levels to help improve this F-Droid repository parser.

By participating in this project, you help make alternative package distribution more accessible and reliable.

---

## Code of Conduct

We expect all contributors to maintain a respectful, welcoming, and collaborative environment. Please be considerate, professional, and supportive in all issues, pull requests, and discussions.

## How Can I Contribute?

### 1. Reporting Bugs
If you find a bug, parser error, or edge case where an F-Droid index file fails to parse correctly:
* Check the **Issues** tab to ensure it hasn't already been reported.
* Open a new issue using a clear, descriptive title.
* Include steps to reproduce the issue, along with a snippet or URL of the target F-Droid index file causing the failure.
* Provide details about your environment (e.g., framework version, OS).

### 2. Suggesting Enhancements
Have an idea for a new feature, performance optimization, or better format support?
* Open an issue explaining the proposed change.
* Describe the problem it solves and your vision for the implementation.

### 3. Submitting Pull Requests (PRs)
Ready to contribute code or fix a bug? Follow these steps:
1. **Fork** the repository and create your branch from `main`.
2. Make your modifications. Keep changes focused and self-contained.
3. Ensure your code compiles successfully without regressions.
4. **Test your changes**: Include or update corresponding tests to ensure the parser handles your modifications reliably.
5. Commit your changes with clear, concise commit messages.
6. Submit a **Pull Request** targeting the `main` branch.
7. Provide a detailed description in the PR explaining what was changed and why.

---

## Development Guidelines

* **Clean Architecture:** Keep parsing logic separate from data models and external network utilities.
* **Format Compliance:** Ensure adjustments strictly respect standard F-Droid repository index schemas.
* **AI Co-Author Credits:** To maintain full transparency regarding the development process, an AI co-author credit may be included or preserved in project logs and collaborative spaces.

## Style & Standards

* Follow standard formatting and structural conventions native to the codebase.
* Prefer clean, descriptive variable names.
* Keep the codebase lean, structured, and performant.

Thank you for helping us build a better ecosystem!
